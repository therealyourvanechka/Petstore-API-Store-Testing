# Petstore API Store Testing

Автоматизированное тестирование блока заказов `/store` публичного API Petstore

## О проекте

Проект направлен на проверку корректности работы API для управления заказами

Покрыты основные сценарии взаимодействия с системой:

- создание заказа
- получение заказа
- удаление заказа
- получение статистики по статусам

Тестирование выполнено с использованием Python, pytest и requests

## Структура проекта

```
petstore_qa/
├── tests/
│   ├── helpers.py            
│   ├── conftest.py           
│   ├── test_inventory.py     # GET /store/inventory
│   ├── test_order_create.py  # POST /store/order
│   ├── test_order_get.py     # GET /store/order/{orderId}
│   └── test_order_delete.py  # DELETE /store/order/{orderId}
├── reports/                  # HTML-отчёты после запуска
├── requirements.txt
├── pytest.ini
├── .gitignore
└── README.md
```

## Маркеры

| Маркер | Описание |
|---|---|
| `smoke` | Базовые тесты (API живой) |
| `critical_path` | Ключевые сценарии |


## Запуск

```bash
# Установить зависимости
pip install -r requirements.txt

# Запустить все тесты
pytest

# Запустить только smoke
pytest -m smoke

# Запустить критический путь
pytest -m critical_path

# Запустить конкретный файл
pytest tests/test_order_create.py

# Запустить с выводом print()
pytest -s
```

После запуска HTML-отчёт появится в `reports/report.html`

## Найденные баги

**POST /store/order не валидирует обязательные поля**

При отправке пустого тела возвращает 200 OK и создаёт заказ с дефолтными значениями (petId=0, quantity=0), заказ без привязки к питомцу лишён смысла, поэтому как минимум поле petId должно быть обязательным

**POST /store/order принимает невалидные статусы**

Принимает произвольные значения поля status (zombie, $%#, 123, "") и успешно создаёт заказ, отсутствует валидация enum-значений, хотя ожидается ограниченный набор (placed, approved, delivered)

**POST /store/order не проверяет уникальность идентификатора заказа**

При создании заказа с уже существующим id сервер не возвращает ошибку, а перезаписывает существующую записьб в результате данные предыдущего заказа теряются

**POST /store/order не ограничивает заказы на одного питомца**

Позволяет создать несколько заказов для одного и того же petId без ограничений, это может приводить к логическим противоречиям ( один и тот же питомец может быть заказан несколько раз одновременно или повторно заказан после доставки)

**GET /store/inventory возвращает невалидные статусы питомцев**

В ответе метода могут присутствовать статусы, не входящие в допустимый список (available, pending, sold), что указывает на отсутствие валидации данных

**GET и DELETE /store/order/{orderId} некорректно обрабатывают невалидные входные данные**

При передаче строковых значений (abc) или отрицательных чисел (-1) возвращает 404 Not Found, не различая невалидный ввод (400 код) и отсутствие ресурса
